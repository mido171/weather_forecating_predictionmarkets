HKG Tmax Point-Forecast ML Strategy Deep Analysis and Next-Round Specification
Scope boundary

This memo is only about point forecasting: minimizing MAE/RMSE against the HKO Daily Extract Absolute Daily Max (deg. C) target. It excludes market pricing, trading, EV, Kelly, order books, and probability-bucket calibration. Probability-bucket work was a separate task about converting an official point forecast into calibrated settlement probabilities, not the point-MAE task here.

Public-source cross-check: the HKO climate page exposes Daily Extract resources and states climate data is updated every working day before 2 p.m. up to the previous day, which supports treating Daily Extract as settlement truth rather than same-day predictor data. The HKO local forecast page states regular local forecast updates occur around 45 minutes past each hour, plus 16:15 and 23:15 HKT, which is directly relevant to why the late T-1 23:59 cutoff is strongest. The HKO OpenData local forecast endpoint exposes current forecastDesc, outlook, and updateTime fields, but the archive correctly treats this as secondary confirmation rather than the primary historical apples-to-apples Info.gov anchor.

1. Executive Verdict
1.1 Is there a genuinely promotable ML point-forecasting edge?

No.

The archive shows a real but small leakage-safe point-forecast improvement over the raw official HKO local forecast. The best research model is the broad residual ensemble from the 2026-07-05 experiment:

Do not deploy as a promoted point-forecast model.

The result is good enough to keep as a research benchmark, not good enough to treat as a robust production edge.

The next research step should be one terminal, tightly scoped experiment using the only major still-plausible signal not properly isolated in the current runs:

lag-safe official forecast residual memory

If that experiment does not beat A7 by a meaningful margin, the project should stop trying to beat the official point forecast using only the current public HKO/Info.gov source set.

3. What Worked
3.1 Bias correction worked

The official forecast at T-1 23:59 has a persistent negative bias:

Raw official bias on broad frame: -0.122935°C
A7 final residual ensemble bias: -0.000486°C

The ML system almost completely removed average bias.

The simplest 0215 grouped residual method also showed the same effect:

Raw official bias: -0.122857°C
B3 grouped residual shrinkage bias: +0.012705°C

So the first reliable edge is not “discovering new meteorology.” It is correcting a stable official underforecast tendency.

3.2 Residual modeling worked better than direct absolute prediction

The direct absolute LGBM model failed:

A8 direct absolute LGBM MAE: 0.949068°C
Raw official MAE: 0.930858°C
A7 residual ensemble MAE: 0.898665°C

This proves the official forecast max should remain the anchor. The model should predict:

residual = actual HKO Daily Extract Tmax - official forecast max

not absolute Tmax from scratch.

3.3 Forecast revisions contained real signal

Broad residual-ML ablation:

A0 raw official MAE: 0.930858
A1 grouped residual MAE: 0.924794
A2 revision residual LGBM MAE: 0.914367

A2 improved over A1 by:

0.010427°C

That is meaningful relative to the total A7 gain of 0.032193°C.

The path of official forecast revisions contains information not fully captured by the latest official max alone.

4. What Failed
4.1 Broad ML improved MAE by only 0.032°C because the official anchor is already strong

The raw official forecast is already near 0.93°C MAE. This is not a weak baseline.

The final A7 correction improved MAE by:

0.032193°C

but the model’s residual signal was weak:

mean absolute correction: about 0.204°C
median absolute correction: about 0.171°C
correlation(true residual, A7 correction): about 0.248

That is real signal, but not strong enough to support a large, robust all-row correction.

4.2 A7 mainly learned an upward correction

Row-level sign autopsy:

Raw official condition	Rows	Raw MAE	A7 MAE	A7 gain
Official forecast too low	2,960	1.001993	0.866067	+0.135926
Official forecast too high	2,458	0.925102	0.998589	-0.073487
Official forecast exact	211	0.000000	0.191931	-0.191931

This is the key failure mode.

The model corrected the official underforecast bias, but it did not reliably know when the official forecast was already correct or too high.

4.3 C1/C2/C3 failed because pruning and routing removed useful small corrections

Selective-router results:

Model	MAE	Gain vs raw	Difference vs A7
A7 current reproduction	0.898665	+0.032193	—

The router did not fail because there was no signal. It could rank benefit deciles: high predicted-benefit deciles had higher realized improvement. But it failed as a final point forecaster because:

A7’s small all-row corrections were useful even on many rows the router abstained from.
The router’s applied corrections did not beat A7’s corrections on applied rows.
Feature pruning removed some weak but collectively useful interactions.
The apply-rate drifted by split and month.

The key row-level finding:

C2 abstained on 2,828 rows.
On those abstained rows:
raw MAE = 0.900566
A7 MAE = 0.895227
C2 MAE = 0.900566

So abstention discarded small but real A7 gains.

On applied rows:

raw MAE = 0.961442
A7 MAE = 0.902137
C2 MAE = 0.905317

So C2 helped raw official but still failed to beat A7.

4.4 Tail specialists were not useful for point MAE

The C3 tail overlay activated on only about three primary-cutoff rows. It was effectively inert.

The current tail signal is useful diagnostically but not yet deployable as a point-MAE overlay.

4.5 Station-network gradients looked important but did not move MAE after HKO hourly state

A4 added station-network features:

A3 HKO hourly-state residual LGBM MAE: 0.900754
A4 station-network residual LGBM MAE: 0.901236

That is a slight MAE regression.

Feature importance ranked network variables highly, but ablation says they were mostly redundant after official forecast, revision, calendar, and HKO hourly state. Network features may help tail/RMSE slightly, but they are not proven MAE-positive as a full block.

4.6 Text, warning, and cyclone features did not improve all-row MAE

A5 added text/warning features:

A4 MAE: 0.901236
A5 MAE: 0.901910

They improved some p90 behavior but hurt MAE. They should remain diagnostic or limited interaction features, not a broad feature block.

4.7 Target memory had weak incremental value

A6 added target-memory features:

A6 MAE: 0.900630

That is a small improvement versus A5, but almost no improvement versus A3:

A3 MAE: 0.900754

The target-memory implementation did not isolate official forecast residual memory, which is different from plain target thermal memory. That is the most important still-plausible next signal.

This is the main reason all-row ML correction is dangerous.

The late forecast issue captures the strongest same-source information. The 15:00 failure is real under the strict selector because no strict lead-1 Info.gov local min/max anchor is available before that cutoff in the implemented audit. The 16:30 provenance audit almost reaches viable coverage but still falls below the configured 80% post-2011 threshold.

5.5 Revisions are informative, but the final official max already absorbs much of them

A2 revision features helped by 0.010427°C after A1, so revisions matter. But A2 still had MAE 0.914367, far above A7 0.898665, and the biggest remaining jump came from HKO hourly state. The revision path alone is not enough.

6. The Best Next Strategy To Beat Official
6.1 Hard recommendation

Run exactly one more existing-source point-forecast experiment:

Experiment 0003:
Lag-safe official forecast residual memory

This is the best next lane because the existing experiments have already tested:

static grouped residual correction
forecast revision features
HKO hourly thermal/moisture state
station-network gradients
text/warning regimes
target thermal memory
broad residual ensemble
selective no-harm routing
tail overlay routing
direct absolute prediction

The remaining plausible signal is not simply “recent HKO was hot.” It is:

Has the official HKO forecast itself been systematically too low or too high for this exact station in the last few settled days/weeks?

That is official residual memory, not target memory.

6.2 Exact hypothesis
Recent lag-safe official forecast residuals contain short-term forecaster/station/regime bias information that is not fully captured by latest official max, forecast revisions, HKO hourly state, station-network gradients, or calendar features.

Examples:

If the official forecast has been undercalling HKO Headquarters Tmax for several settled days, the next forecast may also be slightly too low.

If the official forecast has recently been too high during cloudy/rainy maritime regimes, upward corrections should be suppressed.

If recent absolute residuals are elevated, the current official max may be in a fragile regime where larger corrections are more defensible.
6.3 Why this dominates the alternatives

This lane is better than another router/tail experiment because:

C2/C3 already tested routing and failed to beat A7.
A4/A5 already tested broad network/text additions and failed to improve MAE.
A8 already proved direct absolute prediction is worse.
A7 already captured generic bias and feature interactions.
Official residual memory attacks the remaining problem directly: correction sign and current official-forecast vulnerability.

It is also low-cost and leakage-controllable.

6.4 Exact target variable and sign convention

Use residual target:

residual_c[T] = actual_hko_daily_tmax_c[T] - official_forecast_max_c[T, cutoff]

Prediction:

prediction_c[T] = official_forecast_max_c[T, cutoff] + residual_hat_c[T]

Positive residual means:

official forecast was too low

Negative residual means:

official forecast was too high

No broad hyperparameter search.

LightGBM objective: MAE / L1 residual objective
boosting rounds: 120-180
num_leaves: small to moderate
learning_rate: fixed or tiny two-value grid

feature_fraction: fixed
bagging_fraction: fixed
seed: fixed

Search only:

The purpose is to test the residual-memory signal, not rediscover generic model hyperparameters.

6.12 Exact acceptance gates

Promotion requires all gates:

Leakage gate:
  leakage_audit.status == pass
  total_violations == 0

Row identity gate:
  D5, A7, and A0 scored on identical primary rows

Development MAE gate:
  D5 improves over A7 by >= 0.012°C on the 2011-2023 nonsealed frame
  D5 improves over raw official by >= 0.045°C on the same frame

Presealed holdout gate:
  D5 improves over A7 by >= 0.008°C on 2022-2023
  D5 improves over raw official by >= 0.040°C on 2022-2023

RMSE/p90 no-harm gate:
  D5 RMSE no worse than A7 by more than 0.005°C
  D5 p90 AE no worse than A7 by more than 0.010°C

Slice no-harm gate:
  no month with n >= 100 worse than A7 by > 0.015°C
  no season worse than A7 by > 0.010°C
  no official forecast max bin with n >= 150 worse than A7 by > 0.020°C

Feature-family proof gate:
  residual-memory feature block must improve MAE by >= 0.006°C versus the same pruned model without the block on rolling + presealed rows

Sealed confirmation gate:
  sealed is report-only
  after freeze, sealed D5 must not reverse the A7 edge by more than 0.005°C

If these gates fail, do not promote.

Construct selected official anchors for prior target dates d.
Join prior settled target labels for d.

official_residual_c[d, c] = target_tmax_c[d] - selected_official_forecast_max_c[d, c]
Permit a prior residual only if:
d <= T - 2 days

published_at_hkt[d] <= cutoff_at_hkt[T]

if and only if first-publication timestamps are available and audited.

Default:

lag1 disabled

10. Hard Red-Team
10.1 Where could the recommended plan leak?
Lag1 or publication timing leakage

Risk:

Using target residuals from T-1 before Daily Extract for T-1 was actually published.

Mitigation:

Default min_lag_days = 2.
Lag1 disabled unless row-level first-publication timestamp proves availability before cutoff.
Future residual-memory calculation

Risk:

Rolling residual means accidentally include residuals from T or future dates.

Mitigation:

Every memory feature must expose residual_memory_max_source_date.
Leakage audit must assert residual_memory_max_source_date <= target_date - 2 days.
Sealed-confirmation leakage

Risk:

2024+ residuals influence model selection, stack weights, feature selection, or thresholds.

Mitigation:

sealed_confirmation rows are final report-only.
No stack weights, shrinkage parameters, feature filters, or hyperparameters may use sealed rows.
Fold-local normalization leakage

Risk:

Residual-memory climatology or shrinkage pools use all-history statistics.

Mitigation:

All grouped residual baselines, climatology, shrinkage, and feature normalization must be fit fold-locally.
