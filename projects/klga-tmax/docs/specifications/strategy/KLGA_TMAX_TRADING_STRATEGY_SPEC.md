# KLGA Tmax Polymarket Trading System — Full Strategy Specification

## 0. Mandate

Build a leakage-safe, as-of, multi-cutoff, probabilistic forecasting and trading system for Polymarket markets that resolve to the highest temperature recorded at LaGuardia Airport Station (`KLGA`) on a given New York local calendar day.

This system must be built as if competing against highly sophisticated traders. The required design goal is not a pleasant weather model; it is a disciplined quantitative trading engine that extracts every defensible bit of signal from forecasts, observations, history, settlement behavior, and market prices.

The system must produce:

```text
1. A full probability distribution over whole-degree Fahrenheit KLGA daily highs.
2. A probability for every Polymarket outcome bucket.
3. A fair price for every outcome bucket.
4. A trade/no-trade decision using orderbook depth, slippage, uncertainty, and risk limits.
5. Full auditability showing exactly which data was available at decision time.
```

The system must never optimize only for point-forecast MAE. MAE is a diagnostic; market profitability comes from calibrated probability distributions and disciplined execution.

## 1. Non-negotiable principles

### 1.1 No leakage

No feature may use data that would not have been available by the forecast cutoff. This applies to:

```text
weather forecasts,
model runs,
observations,
analysis products,
settlement labels,
prior-day high errors,
Polymarket prices/orderbooks,
source availability metadata.
```

The core eligibility rule is:

```python
feature_is_eligible = source_available_at_utc <= cutoff_utc
```

If actual availability is not known historically, use the source-specific conservative lag rules defined in the data-acquisition specs.

### 1.2 Output probabilities, not just point forecasts

The final weather forecast must be a probability mass function over integer temperatures:

```text
P(Y = 50°F), P(Y = 51°F), ..., P(Y = 115°F)
```

Default temperature grid:

```python
TEMP_GRID_F = list(range(50, 116))
```

The grid is intentionally wide. If historical KLGA/Wunderground values outside this grid are found, extend the grid before training.

### 1.3 Train over each source's available history; do not force common intersection

Different datasets have different historical ranges. The system must not throw away long-history MOS/Wunderground/ASOS data merely because AI models begin later. Each source trains in its own valid historical window and contributes through out-of-fold expert predictions plus missingness-aware stacking.

### 1.4 Walk-forward only

Random splits are forbidden. Validation must simulate time:

```text
Train on past -> predict future.
```

Every score reported to the user must come from walk-forward, out-of-fold predictions.

### 1.5 Trade only when edge survives uncertainty

A forecast edge is not enough. A trade is allowed only when:

```text
model_edge > slippage + fees + calibration_uncertainty + model_risk_buffer + minimum_edge_threshold
```

A no-trade decision is an intended profitable behavior, not a failure.

## 2. Market target definition

For target date `T`:

```text
station: KLGA
source: Wunderground historical daily station data
timezone: America/New_York
window: 00:00:00 through 23:59:59 local time on date T
unit: whole degrees Fahrenheit
label: Wunderground-reported highest temperature for the local day
```

Canonical notation:

```text
Y_T = integer °F Wunderground daily high at KLGA on local date T.
```

All model features must be aligned to this local-day target, not to a UTC day.

## 3. Forecast cutoffs

The system runs four mandatory forecast snapshots per target date.

| cutoff_id | Local time | Primary purpose |
|---|---|---|
| `T_MINUS_1_STOCKHOLM_1500` | 15:00 Europe/Stockholm on T-1 | Early alpha; lower accuracy but potentially more exploitable market pricing. |
| `T_MINUS_1_STOCKHOLM_1915` | 19:15 Europe/Stockholm on T-1 | Main T-1 forecast after more 12Z guidance becomes available. |
| `T_MINUS_1_STOCKHOLM_2230` | 22:30 Europe/Stockholm on T-1 | Late T-1 update with more ensemble/high-res guidance. |
| `PRE_LOCAL_DAY_NYC_2350` | 23:50 America/New_York on T-1 | Best pre-local-day forecast immediately before KLGA target day starts. |

Implementation rule:

```python
from zoneinfo import ZoneInfo

TARGET_TZ = ZoneInfo("America/New_York")
TRADER_TZ = ZoneInfo("Europe/Stockholm")
UTC = ZoneInfo("UTC")
```

All cutoffs must be generated by timezone-aware conversion, not by fixed offsets.

Notation:

```text

```

Every expert must produce:


## 9. Expert 1 — Long-history climatology/MOS/station expert

### 9.1 Purpose

This is the stable backbone. It prevents short-history modern/AI models from overfitting.

### 9.2 Inputs

```text
calendar/climatology features
Wunderground actual-history features
IEM MOS features
IEM ASOS/METAR historical features
nearby-station gradients
station group features
```

### 9.3 Training data

Use the longest available period:

```text
Wunderground labels: earliest available, target 2000 onward.
IEM MOS: product-specific history, target 2000/2003 onward depending product.
ASOS/METAR: earliest available, target 2000 onward.
```

Do not require modern model features.

### 9.4 Model form

Train two components:

1. Point/residual model:

```text
Base prediction = robust ensemble of ridge regression + gradient-boosted trees.
Target = Wunderground KLGA daily high.
```

2. Residual distribution model:

```text
Residual = actual high - base prediction.
Condition residual distribution on day-of-year, MOS spread/disagreement, recent volatility, wind/cloud/precip features if available.
```

### 9.5 Output construction

For each integer `k`:

```text
P_long_history(Y=k) = P(residual in interval [k-0.5 - point, k+0.5 - point])
```

Smooth residual distribution with a minimum variance floor:

```text
sigma_floor = 1.2°F
```

Do not allow an expert to output a distribution narrower than the floor unless calibration proves it out-of-sample.

## 10. Expert 2 — Dynamic bias-corrected weighted composite

### 10.1 Purpose

This expert is the central point-forecast anchor and a strong benchmark. It combines as many models as possible, bias-corrects them by recent error with exponential decay, weights them by recent skill, and converts the composite into a calibrated distribution.

### 10.2 Candidate raw model forecasts

Candidate forecasts include:

```text
MOS product max/temp features
NBM deterministic Tmax/hourly peak
HRRR hourly peak/Tmax proxy
RAP hourly peak/Tmax proxy
GFS hourly peak/Tmax
GEFS ensemble mean/median
IFS operational
IFS ENS mean/median
AIFS deterministic
AIFS ENS mean/median
AIGFS deterministic
AIGEFS mean/median
Open-Meteo exact-run forecasts
raw archive equivalents if available
```

Every candidate forecast must be converted into a scalar target-day forecast:

```text
raw_forecast_{m,T,c} = model m's best scalar forecast for target date T at cutoff c.
```

The scalar should be the best validated representative of that source:

```text
TMAX field if strong and available,
else hourly 2m temp max over market day,
else product-specific max temp forecast,
else ensemble mean/median target-day member max.
```

### 10.3 Error history

For model/source `m`, target date `d`, and cutoff `c`:

```text
error_{m,d,c} = raw_forecast_{m,d,c} - Y_d
```

At forecast date `T` and cutoff `c`, only use historical errors for dates `d` such that:

```text
label_available_at_utc(d) <= cutoff_utc(T,c)
```

For T-1 cutoffs, this normally means dates through T-2.

### 10.4 Exponentially weighted bias

For half-life `h_bias`:

```python
age_days = (T - d).days
weight_d = 0.5 ** (age_days / h_bias)
bias_m = sum(weight_d * error_m_d for d in eligible_dates) / sum(weight_d)
```

Candidate half-lives:

```text
7, 10, 14, 21, 30, 45 days
```

Default starting value:

```text
21 days
```

The training process chooses the best half-life by walk-forward validation, separately by cutoff and model family if sample size permits.

### 10.5 Bias-corrected forecast

```text
corrected_forecast_{m,T,c} = raw_forecast_{m,T,c} - bias_{m,T,c}
```

### 10.6 Exponentially weighted MAE

After bias correction, compute recent skill:

```python
abs_error_corrected_m_d = abs((raw_forecast_m_d - bias_m_d) - Y_d)
mae_m = EWMA(abs_error_corrected_m_d, half_life=h_mae)
```

Candidate half-lives:

```text
21, 30, 45, 60, 90, 120 days
```

Default starting value:

```text
60 days
```

### 10.7 Skill weights

Primary weighting formula:

```python
score_m = 1.0 / ((mae_m + mae_floor) ** p)
weight_m = score_m / sum(score_all_available_models)
```

Candidate hyperparameters:

```text
mae_floor: 0.75, 1.00, 1.50°F
p: 1.0, 1.5, 2.0
```

Default:

```text
mae_floor = 1.0°F
p = 1.5
```

Alternative formula for validation:

```python
score_m = exp(-mae_m / temperature)
```

Candidate temperatures:

```text
0.75, 1.0, 1.5, 2.0
```

The primary formula is used unless the alternative improves walk-forward log loss and CRPS.

### 10.8 Model-family shrinkage

To prevent one family from dominating due to correlated clones, apply family caps:

```text
MOS family max total weight: 35%
NBM/NBMQMD family max total weight: 35%
High-res HRRR/RAP/RRFS family max total weight: 35%
Global deterministic family max total weight: 30%
Global ensemble family max total weight: 40%
AI family max total weight: 25% until 2 full warm seasons of OOF proof exist
Open-Meteo auxiliary family max total weight: 15%
```

After applying family caps, renormalize weights.

### 10.9 Composite point forecast

```python
composite_point_T_c = sum(weight_m * corrected_forecast_m for m in available_models)
```

Store all component weights and corrected forecasts for audit.

### 10.10 Composite residual distribution

Historical residual:

```text
residual_{T,c} = Y_T - composite_point_{T,c}
```

Model residual distribution conditioned on:

```text
cutoff_id
season/day_of_year
composite model spread
ensemble spread
NBM std dev
MOS product spread
HRRR/RAP/NBM disagreement
cloud_bust_risk
storm_outflow_risk
sea_breeze_risk
backdoor_front_risk
recent residual volatility
```

Distribution construction:

```text
1. Use empirical residual analog distribution from nearest historical regimes.
2. Blend with parametric normal/t distribution with scale predicted by a residual-scale model.
3. Apply variance floor.
```

Default variance floor:

```text
sigma_floor = 1.1°F for late/pre-day cutoff
sigma_floor = 1.3°F for early T-1 cutoff
```

Output:

```text
P_dynamic_composite(Y=k)
```

### 13.1 Purpose

### 13.3 Member-level daily Tmax

For each member:

```text
member_tmax = max(2m temperature over target local day at KLGA/pseudo-point method)
```

For models with 3h/6h output, compute native-step max and learn calibration bias versus observed Wunderground daily high.

### 13.4 Probability construction

Raw member probabilities:

```python
P_raw(Y >= k) = count(member_tmax >= k) / n_members
```

Calibrate raw probabilities by threshold and regime:

```text
P_calibrated(Y >= k) = isotonic_or_logistic_calibration(P_raw, spread, model_family, season, regime)
```

Output PMF:

```python
P(Y=k) = P(Y>=k) - P(Y>=k+1)
```

Ensure nonnegative probabilities and sum to 1.

```text
HRRR/RAP point
850/925 temps
10m/925 wind direction
cloud risk
shortwave forecast
precip/storm risk
ensemble spread
model disagreement
day_of_year
recent observed highs/dewpoints
coastal/inland gradients
sea-breeze/backdoor-front proxies
```

### 16.3 Distance metric

Use standardized features. Distance:

```python
distance = sqrt(sum(w_i * (x_i - x_i_hist)^2))
```

Feature weights `w_i` are tuned by walk-forward validation.

### 16.4 Analog selection

Default:

```text
nearest 50 analog days from training history
minimum 25 analogs required
maximum same-year leakage: none; only dates before prediction date
```

If fewer than 25 analogs exist, back off to broader analog criteria.

### 16.5 Output

Use empirical residuals:

```text
residual_hist = Y_hist - composite_point_hist
P_analog(Y=k) = empirical/smoothed distribution of composite_point_current + residual_hist
```

Apply kernel smoothing with bandwidth:

```text
0.75°F default, tuned by validation
```

## 17. Expert 9 — Settlement-source reconciliation expert

### 17.1 Purpose

The market resolves from Wunderground. A 1°F source discrepancy can decide a bucket. This expert models the probability that Wunderground differs from other observation-derived highs.

### 17.2 Inputs

```text
historical Wunderground daily high
IEM ASOS daily high
one-minute-derived max
URMA estimated max
station/time-of-peak diagnostics
month/season
temperature regime
cloud/precip/wind regime
```

### 17.3 Output

A discrete adjustment distribution:

```text
P(delta_settlement = -2)
P(delta_settlement = -1)
P(delta_settlement = 0)
P(delta_settlement = +1)
P(delta_settlement = +2)
```

where:

```text
delta_settlement = Wunderground_high - meteorological_model_high_basis
```

Apply by convolution:

```python
P_settlement_adjusted(k) = sum_delta P_weather(k - delta) * P_delta(delta)
```

This expert should usually be near zero adjustment, but it protects threshold markets.

## 18. Final meta-ensemble

### 18.1 Expert inputs

The final combiner receives:

```text

P_dynamic_composite
P_nbm

P_global_ensemble
P_ai
P_obs_correction

```

plus regime/missingness features:

```text

source_available flags
source_age_hours
ensemble spread
model disagreement
cloud/storm risk
sea-breeze risk
backdoor-front risk
recent residual volatility
sample-size flags for short-history sources
```

### 18.2 Primary combination method: regularized log-opinion pool

For each integer `k`:

```python
log_score_k = intercept_k
for expert j:
    log_score_k += w_j(x) * log(max(P_j(k), epsilon))
P_final(k) = exp(log_score_k) / sum_k exp(log_score_k)
```

Defaults:

```text
epsilon = 1e-6
expert weights constrained >= 0
sum expert weights bounded between 0.5 and 2.0 before normalization
short-history expert weights L2-regularized strongly toward 0
```

### 18.3 Regime-aware weights

Weights are functions of regime features. Implementation options, in order:

1. Start with per-cutoff static weights learned by constrained optimization on OOF log loss.
2. Add regime interactions using a shallow gradient-boosted or regularized multinomial/linear gating model.
3. Only keep regime-aware gating if it improves OOF bucket log loss and calibration.

The gating model must not overfit. Minimum sample requirement:

```text
At least 500 OOF target-days for a regime interaction to be eligible globally.
At least 100 OOF target-days for a station-specific interaction in multi-station training.
```

### 18.4 Fallback combination method

If log-opinion pool becomes unstable due to expert zero probabilities or sample size, fallback to linear pool:

```python
P_final(k) = sum_j w_j(x) * P_j(k)
```

The fallback must be explicitly logged:

```text
combiner_mode = log_pool | linear_pool_fallback
fallback_reason
```

## 19. Calibration

### 19.1 Calibration levels

Calibrate at three levels:

```text
1. Integer PMF P(Y=k)
2. Threshold CDF probabilities P(Y>=k)
3. Market bucket probabilities
```

### 19.2 Threshold calibration

For each threshold `k` in `TEMP_GRID_F`:

```text
raw_p_ge_k = sum_{j>=k} P_final(Y=j)
observed_ge_k = 1[Y >= k]
```

Fit isotonic calibration or logistic calibration:

```text
calibrated_p_ge_k = Cal_k(raw_p_ge_k, regime_features_optional)
```

After calibrating thresholds, enforce monotonicity:

```text
P(Y>=k) >= P(Y>=k+1)
```

If calibration violates monotonicity, apply monotone rearrangement:

```python
for k ascending:
    calibrated_survival[k+1] = min(calibrated_survival[k+1], calibrated_survival[k])
```

Then derive PMF:

```python
P(Y=k) = P(Y>=k) - P(Y>=k+1)
```

Normalize and floor:

```text
prob_floor = 1e-5 before final normalization
```

### 19.3 Regime-specific calibration

Fit separate calibrators when sample sizes allow:

```text
by cutoff_id
by warm season vs cool season
by high model-disagreement regime
by sea-breeze-risk regime
by cloud/storm-risk regime
```

Minimum sample:

```text
500 OOF examples per calibrator preferred.
250 absolute minimum.
```

If below sample threshold, use global calibrator.

### 19.4 Bucket probability derivation

For a market bucket:

```text
below_or_equal high=H:
    P = sum_{k<=H} P(Y=k)

above_or_equal low=L:
    P = sum_{k>=L} P(Y=k)

bounded_range low=L high=H:
    P = sum_{L<=k<=H} P(Y=k)

exact k:
    P = P(Y=k)
```

Bucket probabilities must sum to approximately 1 across mutually exclusive outcome sets. If they do not because of parsing/coverage, market must be marked non-tradable until resolved.

## 20. Training and validation protocol

### 20.1 Multi-station training

Train on KLGA plus selected nearby/regional stations to increase sample size for regimes. Use Wunderground/actual labels where available; station-specific target definitions must be consistent.

Station-level features:

```text

coastal/inland group
urban/coastal flag
station climatology
station-specific recent bias
```

Then fine-tune/calibrate specifically to KLGA and Wunderground settlement.

### 20.2 Walk-forward folds

Default annual folds:

```text
Train <= 2018-12-31 -> predict 2019
Train <= 2019-12-31 -> predict 2020
Train <= 2020-12-31 -> predict 2021
Train <= 2021-12-31 -> predict 2022
Train <= 2022-12-31 -> predict 2023
Train <= 2023-12-31 -> predict 2024
Train <= 2024-12-31 -> predict 2025
Train <= 2025-12-31 -> predict 2026
```

If a source starts later, it participates only in folds after sufficient history exists. Its OOF predictions are missing before then.

### 20.3 Source-specific OOF predictions

Every expert must produce out-of-fold predictions before the meta-combiner trains. The meta-combiner may never train on in-sample expert predictions.

Workflow:

```text
for each fold:
    train each expert using only training dates and source-eligible rows
    predict validation dates
    store expert OOF PMFs
train meta-combiner on stored OOF PMFs
```

## 22. Source audition and pruning rules

No source is discarded early. Every reasonable source gets an audition. But production inclusion requires proof.

### 22.2 Regime-specific value


If retained only for regime-specific value, the meta-gating model must learn low/zero weight outside those regimes.

### 22.3 Pruning

A source is disabled from production only after:

```text

```

### 24.5 Position sizing

Use fractional Kelly with hard caps.

For binary outcome price `p` and model probability `q`:

```python
kelly_fraction = (q - p) / (1 - p)
```

Use:

```python
position_fraction = kelly_multiplier * max(0, kelly_fraction)
```

Defaults:

```text

max_position_per_outcome = 5% of bankroll
max_position_per_market = 12% of bankroll
max_loss_per_target_date = 8% of bankroll
max_total_weather_exposure = 20% of bankroll
```

Reduce sizing:

```text
50% reduction when model disagreement is high.
50% reduction when outcome bucket boundary is within 0.7°F of posterior mean.
25–75% reduction when book depth is thin.
No trade when bucket parse uncertain or data stale.
```

## 31. Final operating doctrine

The system's operating doctrine is:

```text
Ingest broadly.
Timestamp ruthlessly.
Backtest honestly.
Let every source compete.
Exploit only calibrated probability edge.
Preserve capital when edge is not overwhelming.
```

The full strategy is not a naive average, not NBM-only, not ML-only, and not a meteorology-only forecast. It is a leakage-safe quantitative trading stack where meteorology, historical forecast error, station microclimate, ensemble uncertainty, settlement quirks, and market microstructure all contribute to a single disciplined decision.
